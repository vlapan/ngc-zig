# Session: Future Potential Optimizations

During analysis of the strictly optimized `ngc` codebase, five major algorithmic and memory-layout improvements were identified.

## Optimization Backlog

### 1. Zero-Allocation Country Code Casting (u16)
- **Concept:** Since upstream CSV country codes are strictly 2 ASCII bytes (e.g. `"US"`), we can cast them directly to a `u16` integer (`(c[0]) | (c[1] << 8)`).
- **Hypothesis:** This will entirely eliminate the need for `std.StringHashMapUnmanaged`, string interning, and `alloc.dupe`. The `IpTrie` will no longer need to dynamically map strings to integers, bypassing thousands of hash lookups.
- **Expected Impact:** Massive drop in `instructions retired` and a complete eradication of dynamic string memory overhead.

### 2. Node Layout Refactoring (Structure of Arrays - SoA)
- **Concept:** Convert `TrieNode { left: u32, right: u32, country: u32 }` (AoS) to separate arrays: `lefts: []u32`, `rights: []u32`, `countries: []u16` (SoA).
- **Hypothesis:** By packing country integers perfectly adjacently in RAM, the bottom-up `optimize()` loop will fly through the L1 CPU cache without fetching irrelevant tree traversal pointers.
- **Expected Impact:** Lower cache-misses, faster `cycles elapsed`, and a 16.6% reduction in Trie heap size per node (12 bytes -> 10 bytes).

### 3. File Memory-Mapping (mmap)
- **Concept:** Replace the 64KB `in_buf` streaming `Io.Reader` with direct `std.posix.mmap` (mapping the file directly into virtual memory space).
- **Hypothesis:** Treating the file instantly as a `[]const u8` slice eliminates context-switching and user-space copy overhead.
- **Expected Impact:** Noticeably faster `real time` and `user time` execution.

### 4. Multi-threading the CSV pipelines
- **Concept:** Spawn a `std.Thread` to execute IPv4 parsing/building and IPv6 parsing/building concurrently.
- **Hypothesis:** Since the V4 and V6 pipelines share zero mutable data structures, they can run strictly in parallel across multiple cores.
- **Expected Impact:** Nearly 2x reduction in `real time` wall-clock execution (though `user time` / CPU cycles will remain identical).

### 5. Patricia Trie (Path Compression)
- **Concept:** Compress long chains of empty singular nodes (common in IPv6 prefixes) into a single jump node tracking `prefix_length`.
- **Hypothesis:** Halves the depth of the tree allocation required for deep `/128` subnet isolation.
- **Expected Impact:** Exceptional reduction in `maximum resident set size` specifically for the IPv6 dataset.

## Action Plan
For each of these ideas, we will strictly follow the established protocol:
1. Implement the feature in a sterile manner.
2. Run benchmark suites recording `Max RSS`, `instructions retired`, and `real time`.
3. Verify test output (`make test` and `diff output.txt`).
4. Prove or disprove the hypothesis mathematically before committing.
