
## ETag Desync Fix
Removed `test/*.etag` from `.gitignore` and began tracking them in git alongside the `.csv` files.
**Reason:** If the CSV data is tracked in git, its ETag metadata *must* also be tracked. Previously, doing a `git checkout HEAD -- test/*.csv` would revert the data to the past, but the untracked `.etag` file remained in the future. The `fetch-data.sh` script would send the "future" ETag, receive a HTTP 304 Not Modified, and silently fail to download the data needed to fix the desynchronized CSV. By tracking both, a `git restore test/` or a branch checkout guarantees the ETag matches the exact bytes of the CSV file currently on disk.

## State Management Refactor
Moved all planned tasks, optimizations, and future feature backlogs from static daily notes (like `2026-05-13.md`) into a single mutable state file: `knowledge/tasks.md`.
**Reason:** Daily notes are append-only narratives, meaning future items trapped inside them get "forgotten" in later sessions. `knowledge/tasks.md` now acts as the single source of truth for the project roadmap, providing O(1) discovery at the start of every session without needing to `grep` through history. `KNOWLEDGE.md` has been updated to enforce this new workflow rule.

## Benchmark: Branchless IPv6 Formatting
Implemented the `@clz` hardware zero-counting optimization for the IPv6 text formatter.
- **Goal:** Replace the `inline for` and data-dependent `if (nib != 0 or started)` boolean branch with a deterministic calculation of characters to print.
- **Results:**
  - Instructions retired increased very slightly: `3.896B` -> `3.898B` (+1.8M).
  - CPU cycles elapsed remained identical within the noise floor (~`1.01B`).
  - Max RSS memory remained locked at `46.9MB`.
  - The runtime hovered precisely at `~339ms`.
- **Conclusion:** While conceptually cleaner and mathematically deterministic, it did not yield the massive savings seen in IPv4 because the original boolean flag was already being compiled into highly efficient predicated `CMOV` instructions by LLVM, and bitwise shifts are already 1-cycle operations. The `@clz` approach is committed as it removes data-dependencies from the pipeline.

## Benchmark: Lightweight Index Sorting (Pointer Sorting)
Implemented the `sortIndicesBySizeDesc` optimization.
- **Goal:** Replace `std.mem.sort` on a massive array of 64-byte `IPv6Range` structs with sorting an array of 4-byte `u32` integers, drastically reducing memory bandwidth overhead during physical element swapping.
- **Results:**
  - **Instructions retired PLUMMETED:** `3.89B` -> `2.62B` (A massive reduction of ~1.27 Billion instructions!).
  - **CPU cycles elapsed dropped:** `1.00B` -> `812M` (Saved ~200 Million CPU cycles).
  - **Runtime dropped:** `~330ms` -> `~260ms` (~21% faster execution).
  - **Memory Impact:** Max RSS increased slightly from `44.8 MB` to `46.1 MB` (+1.3MB) because we are now allocating two extra `[]u32` arrays (one for IPv4, one for IPv6) to hold the indices alongside the original struct arrays.
- **Conclusion:** A massive success. Trading 1.3MB of RAM to instantly bypass 1.2 Billion CPU instructions is an exceptional optimization trade-off. The execution is significantly faster, and the automated `make bench` output proved the mathematical CIDR output remained perfectly intact.
